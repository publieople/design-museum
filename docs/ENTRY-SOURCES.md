# 词条来源清单

配套文档：[ENTRY-PIPELINE.md](ENTRY-PIPELINE.md)（阶段 1「发现」与阶段 2「拆解」）、
[ENTRY-SPEC.md](ENTRY-SPEC.md) 第 8 节（refs 白名单与版权）。

**先记住一条**：这份清单是用来「看行为、拆参数」的，不是素材库。
任何站点的代码、样式、图片、字体、文案都不进仓库；实现一律自己写。

## 用法分级

| 级别 | 含义 | 允许做什么 | 不允许做什么 |
| --- | --- | --- | --- |
| **A · 逐组件拆解** | 组件库 / 教程，单个效果边界清楚 | 看演示、读 props 文档、量参数、自己重写 | 复制源码、复制样式表、下载示例素材 |
| **B · 原理与取值参考** | 规范与教程文档 | 读原理、抄「推荐值」到 `spec`（用自己的话） | 整段搬运正文、把文档示例代码贴进 demo |
| **C · 仅灵感** | 作品集 / 获奖站 / 精选目录 | 看整体气质、找「还缺什么效果」 | 逐像素拆解、截图入库、照搬整页布局 |

C 类站点几乎都是**多个效果叠加的成品页**：你看到的「高级感」往往来自排版、留白、图片质量与动效编排的总和，
拆不出单一可命名的效果。把它们当选题雷达，不当拆解对象。

## 按级别怎么用

### A 类：逐组件拆解（主力产线）

1. 打开组件演示页，**先别看代码**，只用眼睛和指针确认：触发是什么、动的是哪部分；
2. DevTools → Elements 面板看命中的属性（`transform` / `filter` / `mask` / 伪元素）；
3. DevTools → Animations 面板录一次交互，读出时长与曲线；CSS 动画直接看 `@keyframes` 名称与 `animation` 简写；
4. 读 props 表，把「作者暴露的参数」翻译成我们的 `controls`（区间可以放宽，默认值取演示里最耐看的那个）；
5. 关掉 JS 再试一次：纯 CSS 能成立的，`tags.tech` 记 `css-only`；必须 JS 的记 `js` 或 `browser-api`；
6. 填六格表（模板见 ENTRY-PIPELINE 模板 A），写出最小实现（20–40 行，零依赖）；
7. 只有六格填满、最小实现能跑，才往 backlog 里加 `candidate`。

### B 类：原理与取值参考

- 用来回答「这个值多少合适」「Safari 支持吗」「无障碍该怎么降级」；
- `spec` 里的推荐值要**带上出处判断**（规范推荐 / 文章实测 / 我们的经验），别把博客的一家之言写成标准；
- MDN 与 web.dev 可以直接进 `refs`；CSS-Tricks 与其它博客只作为 PR 描述里的行为参考。

### C 类：仅灵感

- 每周扫一次即可，只回答一个问题：「最近大家在用哪一类效果，而博物馆还没有？」
- 看到喜欢的效果，**不要截图存进仓库**，而是回到 A/B 类找它的「可命名版本」；
- 如果 C 类站点上有个效果在 A 类里找不到对应物，先写进 backlog 的 `note` 标「待拆」，别急着立项。

## 记录格式

每条候选只留这些信息（与 `docs/entry-backlog.json` 字段一致），**不存截图、不存源码片段**：

```json
{
  "slug": "text-scramble",
  "nameZh": "文字解码",
  "nameEn": "Text Scramble",
  "hall": "motion",
  "shape": "sequence",
  "source": "React Bits https://reactbits.dev",
  "status": "candidate",
  "note": "字符先显示成乱码再逐位落定，逐字显现从一开始就是正确字符。"
}
```

`source` 写「来源名 + 链接」，方便回访；`note` 必须写清「和已有词条的差别」，否则 triage 阶段会被判成同义项。

## 版权与许可红线（与 ENTRY-PIPELINE 第 8 节一致）

- **不复制代码**：A 类组件库即便 MIT，也不整段粘贴；我们零依赖，抄来的实现往往带框架绑定。
- **不复制样式与素材**：配色、图片、SVG、字体、视频一律不用；需要视觉元素就用 CSS 画。
- **不整段搬运文案**：教程与文档的段落用自己的话重写。
- **Uiverse.io 特别注意**：投稿授权由作者单独声明，常见「未标注」状态，视为不可复制。
- **Codrops / Awwwards / Godly 特别注意**：演示里的图片与字体多为第三方授权素材，站点本身也是商业作品。
- **登记**：确实引用了第三方素材（如 CC0 纹理），必须登记 `THIRD_PARTY_NOTICES.md` 并注明来源与许可。
- **refs 白名单**：MDN、web.dev、W3C / CSS spec、Chrome Developers；其它来源在 PR 里说明理由。

## 扫描节奏（摘自 ENTRY-PIPELINE 阶段 1）

| 频率 | 动作 | 产出 |
| --- | --- | --- |
| 每周 30 分钟 | 过一遍本周新看到的链接，判断值不值得进池 | 0–3 条 `candidate` |
| 每月 2 小时 | 按本清单 A 类逐站翻新上架组件 | 5–10 条 `candidate`，其中 2–3 条拆到 `triaged` |
| 每季度 1 小时 | 清池：半年未动的候选删掉或补理由；C 类共性写进选题结论 | 更短的池 + 下一季度方向 |

判断「值不值得进池」只用一句话：**能不能被命名，并且和已有词条不是同义项。**
